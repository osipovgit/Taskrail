Instruction contract: 1.

1. Read the goal, constraints and labelled requirements. Start with the project map
   and entry points. Follow dependencies that affect a decision.
2. Ground claims about completed work in observed evidence. To assess past changes for
   regressions, inspect the relevant patches. Verify deployment targets and inventory
   groups from project source.
3. Assign each requirement an outcome. Give each task a deliverable, expected files,
   observable success conditions and checks. Include failure or empty cases when relevant.
   Use Read to point to useful sources or reports. Add line ranges when they help.
4. For a large report, cite the recorded run once and assign its findings by scope.
   Inspect examples before promising a safe fix. Leave behavior-dependent findings
   for the owning task to investigate and report under the user's criteria.
5. Stop when the implementer can do the work and the reviewer can verify it.
